# API Reference

## Base URL and versioning

The API uses a configurable global prefix. The default local base URL is:

```text
http://localhost:3001/api/v1
```

In deployment, set `PUBLIC_API_BASE_URL` to the externally reachable HTTPS origin so stream-token responses contain absolute URLs. The API version is currently `v1` and the shared package exposes `ContractVersion = "v1"`.

OpenAPI is generated by NestJS and served at:

```text
/api/v1/docs
```

## Authentication

Protected routes require a Supabase access token:

```http
Authorization: Bearer <supabase-access-token>
```

The API verifies the token against `SUPABASE_JWKS_URL` and expects the `authenticated` audience. The verified payload must contain:

```json
{
  "sub": "00000000-0000-0000-0000-000000000000",
  "university_id": "00000000-0000-0000-0000-000000000000",
  "role": "student",
  "email": "student@example.edu"
}
```

The email claim is optional. The subject and university ID must be UUID strings, and the role must be `student`, `admin`, or `owner`.

## Common behavior

All requests and responses should follow the Zod schemas in `packages/shared`. Invalid query parameters are rejected by the global `ZodValidationPipe`. Route authorization is enforced by the JWT, role, and tenant guards.

The API should use the following error shape for future standardized exception handling:

```json
{
  "statusCode": 403,
  "code": "TENANT_ACCESS_DENIED",
  "message": "Cross-tenant access is not allowed",
  "correlationId": "request-correlation-id"
}
```

## Health

### `GET /health`

This route is public and intended for liveness probes.

Example response:

```json
{
  "status": "ok",
  "service": "it-sum-api",
  "version": "0.1.0",
  "timestamp": "2026-08-15T00:00:00.000Z"
}
```

The response is validated with `HealthResponseSchema`.

## Resources

### `GET /resources`

Returns published resources for the authenticated user’s university. The current service returns an empty page when Supabase service-role configuration is absent, which permits local boot without provider credentials. In staging and production, the query requires the `resources` table and filters by `university_id` and `status = 'published'`.

Query parameters:

| Parameter | Type | Default | Description |
|---|---|---:|---|
| `page` | integer | `1` | One-based page number. |
| `pageSize` | integer from 1 to 100 | `24` | Page size. |
| `courseId` | UUID | — | Filters by course. |
| `semesterId` | UUID | — | Accepted by the shared contract; service-level filtering should be added before relying on it. |
| `materialKindId` | UUID | — | Filters by material type. |
| `examPhaseId` | UUID | — | Filters by exam phase. |
| `contributorId` | UUID | — | Filters by contributor. |
| `search` | string up to 200 characters | — | Case-insensitive search against normalized title. |

Example request:

```http
GET /api/v1/resources?page=1&pageSize=24&search=network
Authorization: Bearer <supabase-access-token>
```

Example response:

```json
{
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "universityId": "00000000-0000-0000-0000-000000000010",
      "title": "Computer Networks Summary",
      "normalizedTitle": "computer networks summary",
      "mimeType": "application/pdf",
      "sizeBytes": 1240000,
      "pageCount": 32,
      "driveFileId": "google-drive-file-id",
      "driveMd5": "checksum",
      "modifiedAt": "2026-08-15T00:00:00.000Z",
      "status": "published",
      "visibility": "tenant",
      "downloadAllowed": true,
      "textQuality": 0.98,
      "courseId": null,

      "createdAt": "2026-08-15T00:00:00.000Z",

}
```

### `GET /resources/:id/stream-token`

Issues a short-lived token for a published resource. The route requires an authenticated user. The service first resolves the resource inside the user’s university and then binds the signed token to the resource ID, user ID, and university ID.

Example response:

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresAt": "2026-08-15T00:05:00.000Z",
  "url": "https://api.example.com/api/v1/resources/00000000-0000-0000-0000-000000000001/stream?token=..."
}
```

The token lifetime is controlled by `STREAM_TOKEN_TTL_SECONDS` and is limited by configuration to 30–900 seconds. The URL is generated from `PUBLIC_API_BASE_URL` or the local host and port fallback.

### `GET /resources/:id/stream?token=...`

Streams the Drive-backed PDF. This route is marked public at the JWT guard level, but it requires a valid signed stream token. The token must refer to the same resource ID in the URL. The API then resolves the resource, checks that it is published, and forwards the optional `Range` header to Google Drive.

Supported request headers:

| Header | Behavior |
|---|---|
| `Range: bytes=...` | Requests a partial response from Google Drive and enables `206 Partial Content` behavior when returned. |
| `If-None-Match: <etag>` | Returns `304 Not Modified` when it matches the Drive ETag. |

Response headers may include `Accept-Ranges`, `Cache-Control: private`, `Content-Type`, `Content-Length`, `Content-Range`, `ETag`, and `Last-Modified`.

The stream token URL should not be logged, embedded in long-lived public pages, or reused after expiration.

## Drive administration

### `GET /drive/oauth/start`

Requires `admin` or `owner` role. Creates a signed OAuth state containing the user and university identity and returns the Google authorization URL.

```json
{
  "authorizationUrl": "https://accounts.google.com/o/oauth2/v2/auth?...",
  "state": "eyJhbGciOiJIUzI1NiIs..."
}
```

### `GET /drive/oauth/callback`

This is a public callback because Google redirects without the original bearer token. It requires `code` and `state` query parameters. The API verifies the signed state, exchanges the code, encrypts the refresh token, and upserts the `drive_accounts` row for the original university.

The callback must not accept a user ID or university ID from the browser. Those values come only from the signed state.

### `POST /drive/sync`

Requires `admin` or `owner` role. Reads the saved Drive page token, consumes all available changes pages, saves the next start token, and returns a summary:

```json
{
  "runId": "00000000-0000-0000-0000-000000000020",
  "status": "completed",
  "imported": 4,
  "updated": 2,
  "unavailable": 1
}
```

The current route reports Drive changes but does not yet implement the full resource ingestion pipeline. A future worker must process each change idempotently.

## Frontend integration sequence

A frontend PDF viewer should follow this sequence:

1. Call `GET /resources/:id/stream-token` with the user’s Supabase access token.
2. Keep the returned stream URL in memory rather than persistent storage.
3. Pass the URL to the PDF viewer.
4. Allow the viewer to issue Range requests.
5. If the token expires, request a new token and resume from the last known page.
6. Do not expose `driveFileId` as a direct browser download URL.
